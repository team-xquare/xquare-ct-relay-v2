## 기존 사항에서 수정점
- 기존 서버는 각각의 VM 서버에다가 에이전트를 설치하는 식으로 동작했음
- 다만 에이전트 설치가 귀찮음. 따라서 VM IP + 비밀번호를 저장해 두고, 내부망 자체에서 ssh를 접속해 하나의 게이트웨이 VM이 모아서 중계 서버로 보내는 것을 할 거임
- 추가로 C2 관리자 패널의 UI를 개선하고, 전용 API 키(env에 넣던지 하면 댐)를 사용해, 서버를 추가할 수 있도록 웹  API를 만들어 주어야 함.
- 최종 구조는 아래와 같음
    - 클라이언트 --- ssh --- 외부 공개 서버 --- websocket --- 내부 게이트웨이 VM --- ssh --- 다수의 내부망 서버들
- 데이터베이스에 VM 아이피와 아이피에 대응되는 아이디(유추 불가)를 저장할 것
- 유저는 접속 시에, ssh (접속할 유저 이름)-(VM 아이피에 대응되는 아이디)@xquare.xyz -p 2220 으로 접속할 수 있도록 해야 하며, 유저 이름에 대한 비밀번호를 넣어야지 접속이 되게 해야 함.
- DB는 복잡하게 하지 말고 sqlite 쓰는거루..
- 배포에서는 DockerFile 되게 하장
- 모든 저장은 릴레이 서버가. 게이트웨이는 분배만 하는것!
- 게이트웨이는 로드밸런싱이 되게 해야 함. 여러 개 등록해도 된다는 이야기입니당
